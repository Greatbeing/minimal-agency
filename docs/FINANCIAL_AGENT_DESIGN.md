# 金融算法交易 Agent — 设计方案

> 核心场景：BreakShell 自我模型在算法交易中的应用

---

## 1. 场景定义

### 1.1 问题

传统交易 Agent 的核心盲区：

| 盲区 | 后果 |
|------|------|
| 不知道当前市场是否在自己的训练分布内 | 遇到新型市场机制 → 策略失效 → 巨亏 |
| 不知道自己的预测置信度是否可靠 | 过度自信 → 杠杆过高 → 爆仓 |
| 不知道策略是否已经失效 | 策略衰减 → 不止损 → 回撤扩大 |

### 1.2 BreakShell 方案

```
传统交易 Agent：
  市场数据 → 预测模型 → 交易信号 → 执行

BreakShell 交易 Agent：
  市场数据 → 预测模型 → 交易信号 → 执行
      ↓                    ↑
  自我模型 ──────────────┘
  (编码: 市场状态/预测置信度/策略有效性)
```

---

## 2. 核心设计

### 2.1 自我模型编码什么

| 维度 | 含义 | 数据来源 |
|------|------|----------|
| 市场状态 | 当前市场与训练分布的偏离度 | 波动率/流动性/趋势强度 |
| 预测置信度 | 模型对当前预测的不确定性 | 模型集成分歧/历史准确率 |
| 策略有效性 | 当前策略是否仍然有效 | 近期盈亏比/夏普比率 |
| 能力边界 | 当前市场是否在自己的能力范围内 | 市场状态 × 策略有效性 |

### 2.2 自我模型如何影响决策

```
高能力 + 高置信度 → 正常执行（标准仓位）
高能力 + 低置信度 → 降低仓位 / 观望
低能力 + 高置信度 → 降低仓位 / 谨慎执行
低能力 + 低置信度 → 暂停交易 / 人工介入
```

### 2.3 风险控制层

| 层级 | 触发条件 | 动作 |
|------|----------|------|
| L1 预警 | 自我模型检测到能力下降 | 降低仓位 50% |
| L2 降级 | 市场状态超出训练分布 | 停止新开仓 |
| L3 暂停 | 策略有效性持续下降 | 全部平仓 + 人工审核 |
| L4 紧急 | 单日亏损超过阈值 | 强制平仓 |

## 3. 回测系统设计

### 3.1 回测目标

| 问题 | 验证方式 |
|------|----------|
| 自我模型能否提升收益？ | 对比累计收益 |
| 自我模型能否降低回撤？ | 对比最大回撤 |
| 自我模型能否提升风险调整收益？ | 对比夏普比率 |
| 自我模型能否检测策略失效？ | 对比策略切换延迟 |

### 3.2 回测场景

| 场景 | 描述 | 预期结果 |
|------|------|----------|
| 正常市场 | 波动率/流动性在训练范围内 | 两者差异不大 |
| 极端行情 | 黑天鹅事件（如 2020 新冠） | BreakShell 回撤更小 |
| 市场机制变化 | 交易规则/参与者结构变化 | BreakShell 更快检测失效 |
| 策略衰减 | 策略被市场套利 | BreakShell 主动降仓 |

### 3.3 评估指标

| 指标 | 说明 |
|------|------|
| 累计收益 | 总收益率 |
| 最大回撤 | 峰值到谷底最大亏损 |
| 夏普比率 | 风险调整收益 |
| 卡尔玛比率 | 收益/最大回撤 |
| 策略失效检测延迟 | 从失效到检测的天数 |
| 过度自信率 | 高置信度但实际错误的比率 |

---

## 4. 实现计划

### Phase 1：核心环境
- 金融市场模拟器（价格/波动率/流动性）
- 传统交易 Agent（无自我模型）
- BreakShell 交易 Agent（有自我模型）

### Phase 2：回测引擎
- 回测框架（事件驱动）
- 评估指标计算
- 可视化报告

### Phase 3：对比实验
- 正常市场回测
- 极端行情压力测试
- 策略衰减检测实验
